# UI session lifecycle correction

Approved scope: local Stage 0 correction descended from integration commit
`9e515af911a8d387973e48131d6037d8d96ae4e5`. This is not Stage 1 or release approval.

Each UI page execution owns a fresh SQLAlchemy session through the context-managed
`app.ui.common.get_db` scope. Settings load inside that protected scope. The scope
includes all dependent rendering, actions and lazy ORM access. Every successfully
acquired session closes on normal completion, settings failure, page exception,
`st.stop` and `st.rerun`; exceptions propagate normally. Acquisition failures
propagate without attempting to close an unacquired session.

Existing explicit commits remain the only business commit boundaries. Cleanup
does not commit pending work. Sessions and session-dependent objects must not be
cached or captured for later execution. Session state retains scalar identities,
detached report values and generated bytes only.

Apply this boundary to Dashboard, Explore, Scheme Detail, Review Site Links,
Review Allocation Site Matches, Local Plan Sites, Shortlist, Council Dashboard,
Council Intelligence and Council Intelligence Detail. Preserve page behavior,
selection/export identity, AH qualification, source attribution and committed
actions. Do not change shared engine configuration, dependencies or schema.

Verification must assert connection release before garbage collection or test
teardown, including normal and exceptional exits, repeated reruns/navigation,
independent AppTest instances, lazy loading and transaction behavior. A parent
regression must demonstrate the original leak. The existing offline focused
suite, workflow-context tests and unchanged full rendered/CSV walkthrough remain
acceptance gates. AppTest/download bytes are not browser HTTP or production
acceptance. Baseline acceptance and production release require separate review.
