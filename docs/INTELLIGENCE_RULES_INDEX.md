## 7. Shared evidence foundations: reuse before redesign

| Foundation | Existing support | Material limitation / alignment target |
|---|---|---|
| Subject identity and scope | CountAssessment; FactPosition/OperativeFact; AHClaim; ControlRelationship; WorkItem scope; acquisition-subject keys | Not every legacy scalar carries phase/revision identity; Site co-membership is weaker than G2 containment. Adapt explicitly rather than assume equivalence |
| Claim, value, units, qualifier | CountAssessment metric/precision/bounds; AHClaim qualifier; typed role and evidence category; FactValue state | Legacy estimated/final totals and classifier status buckets flatten meaning; 035 v2 supplies the count target. Missing is never zero |
| Source, quote/locator, evidence version | Document ID/source_url/content_hash; AH passage; ownership snippet; listing field hash/offsets; ledger immutable capture hashes | Optional or absent legacy provenance is not repaired by attaching a guessed source. Document.content_hash is a whitespace-normalised **text** hash, not necessarily original PDF-byte identity |
| Document/decision/observation/assessment dates | Document.downloaded_at; FactPosition.decision_date/status_verified_at; AHClaim.document_date; ownership evidence_date; observed_at; evaluation timestamps | Download time is not document date; check time is not decision date; missing dates stay unknown. Review must preserve each separately |
| Conflict/supersession/uncertainty | OperativeFact conflicts; CountAssessment superseded; AH alternatives/relationships; ownership needs_confirmation/rejected; 033 observation history | General immutable owner correction history is specified in 036, not implemented; automatic correction must not erase source disagreement |
| Method and rule version | ControlRelationship.extraction_method/review_status; listing rule_version; agent policy/prompt/schema versions and input fingerprints | No mandatory identical carrier across all legacy facts; source confidence is not human verification. Explicit adapters need tested loss/unknown semantics |

**Assessment:** contracts are not uniformly complete, but enough useful carriers already exist to reject a new global evidence schema as the first response. Extend/adapt within 035, AH's existing contracts and 036's future decision overlay. Record unsupported fields as unknown; do not make a weak legacy field “verified” by copying it into a richer object.

Two concrete maintenance findings:

1. [`app/pipeline/evidence.py::document_identity_key`](../app/pipeline/evidence.py) still describes Document as having no content hash, while `app/db/models.py::Document.content_hash` exists. **Verified documentation drift**, not evidence that hashing is absent. The model accurately notes known-URL/name dedup does not itself re-fetch/compare a revised document. Revision detection remains a bounded follow-on requirement, not authorisation to crawl.
2. [`app/reporting/affordable_housing_scope.py`](../app/reporting/affordable_housing_scope.py) locally repeats a status-authority table to avoid importing the extraction layer; `subject_relationships.py` intentionally repeats a role literal and tests equality. Duplication alone is not a defect. Prefer parity assertions/explicit mapping at these boundaries; do not remove architectural isolation merely to share a constant.
