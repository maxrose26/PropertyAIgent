## Recovery and trust boundaries

Claim recovery is separate from replay permission. Manual recovery requires the recovery capability, exact expired fence and cleanup evidence. A checkpointed claim can be reclaimed with a higher fence and its retained evidence. An abandoned SOURCE_INTENT becomes SAFETY_BLOCKED; WRITE_INTENT becomes PERSISTENCE_UNCERTAIN. Both raise a global stop without replacing an already-consumed stop. No worker recovery or release path. Known successful fact receipts cannot be overwritten by worker checkpoints or replayed as another effect.

The broker and existing application writer are trusted components, distinct from the runtime SQL worker. The SQL layer cannot make an arbitrary untrusted callback honest. Its deployment must use a reviewed broker login and the existing shared writer capability; this candidate does not provision either or substitute the migration principal for a runtime writer. Disposable B2 tests use the existing privileged application fixture engine, while worker/broker/recovery role denials use real non-superuser logins. Production writer privilege compatibility remains an access-acceptance condition.

Application commits and ledger commits are separate transactions: no distributed exactly-once claim. Durable WRITE_INTENT precedes admission/B2. Lost effect/readback acknowledgement stops all following work and requires reconciliation, with best-effort durable stop and the unresolved intent as a safety barrier. A lost ledger receipt/stop commit cannot be treated as CLOSED or automatically retried. A single finite supervised controller must halt; autonomous consumers are absent. Do not claim crash recovery permits repeating a source call or uncertain write.

The SQL client is not a standalone live controller. It deliberately exposes no workflow, scheduler, secret loader or registration. The concrete outer-controller binding, clean revision, exact authority, operational-role mapping, resource admission and source-specific qualification must pass REVIEW before any live canary. The accepted three-blocked-item storage test and its SQL are unchanged and separate.
