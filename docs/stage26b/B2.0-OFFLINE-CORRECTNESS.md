## Design and scope

Reuse existing exact-reference council retrieval, shared upsert, material-change detector and lifecycle writer. The new verifier uses a conditional UPDATE of the existing successful watermark, guarded by the pre-retrieval status/decision/date/watermark/last-seen state. Facts, watermark, lifecycle events and refresh request commit together. No new schema/version column, distributed lock or matcher. Stale responses fail closed; counters reflect committed events only. Source identity/malformed/contradictory/unsupported appeal input does not verify accepted facts. Explicit status-only withdrawal cannot retain an old grant/date. A date-only correction uses the existing generic lifecycle shape and refresh signal; no summary generation or monitoring execution.

`planning_freshness` is a pure request-local presentation adapter; no query, page redesign or production UI completion is claimed. It separates accepted state, parsed source date, successful watermark, policy overdue/unknown state and current exact-reference failure/conflict. Cadence is supplied, not invented. A later failure can be shown only when a scoped outcome/time is actually available; runtime loss yields attempt unavailable. No council-run success is presented as application verification.

## Attempt persistence assessment — no migration

1. Durable attempt evidence would be needed to promise a buyer the latest exact-reference failed attempt after process loss, or a cross-session per-reference diagnostic audit. It is not required for atomic accepted facts or conservative as-of freshness.
2. ScrapeRun describes council runs, lifecycle records describe established changes, document check fields describe documents; none safely substitutes for an exact-reference failed check. Ephemeral logs may diagnose a current run but their absence cannot mean success.
3. B2.0 uses successful verification plus request-local failure and separately qualified run health. After runtime loss the adapter explicitly says attempt unavailable. This satisfies a bounded no-schema correctness slice, not durable failure-history capability.
4. Batch start is not individual attempt evidence. Any later persisted attempted_at must be written only when that reference is actually dispatched, with interrupted/in-progress ordering semantics; not at batch selection.
5. Attempt columns would NOT solve stale accepted-fact concurrency/atomicity. The existing accepted-state guard and coupled transaction solve that. Therefore no attempt schema is necessary or implemented for B2.0. Return any future durable per-reference audit requirement to REVIEW with its precise product benefit, migration and rollback.

## Evidence and limitations

Additive fixtures distinguish two dated real source-qualified observations from synthetic faults/terminal transitions/concurrency. Source hashes and audit identity are preserved. Withdrawal/appeal/variation real-world source coverage remains unestablished, not benchmark truth. No current council call, full body, production export or model call.

Local SQLite failure injection/deterministic stale-response tests are not claimed as native live PostgreSQL concurrency verification. Accepted-state CAS is conditional SQL, not an in-process lock. Native PostgreSQL simultaneous-worker rehearsal remains a pre-release gate if not available offline. Lost commit acknowledgement reports uncertain persistence, never successful verification; an unchanged retry does not duplicate lifecycle events.
